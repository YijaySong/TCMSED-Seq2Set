# M03 同编码器对照：计算平台运行包

此文件夹可单独上传。它包含 4200 条记录的数据副本、三折固定 ID 清单、四种模型代码、总 runner 和结果核验脚本。数据、GRU 模型源码和划分清单与当前工作区对应文件的 SHA-256 一致；`run_all.py` 在正式运行前会再次核对。

四种方法使用相同的症状嵌入均值编码器结构：128 维症状嵌入取均值，再经 256 维线性层和 Tanh。每个方法独立端到端训练；相同折、种子的编码器从同样的随机初始化规则出发。它们不是共享一份冻结权重。

| 方法代码名 | 输出方式 | 参数量 | 阈值或停止规则 |
|---|---|---:|---|
| `sigmoid_small` | 独立 sigmoid 头 | 40,970 | 验证集选择全局阈值 |
| `sigmoid_matched` | 近 GRU 容量的独立 sigmoid 头 | 535,758 | 验证集选择全局阈值 |
| `classifier_chain` | 固定词表顺序逐标签二元决策 | 41,070 | 各阈值在验证集重新自回归解码后选择 |
| `gru_stop` | 当前 GRU，联合标签/STOP 动作 softmax | 535,819 | 合法动作中贪心选择，STOP 结束 |

与旧版 Classifier Chain 相比，这里的输入编码器相同，验证阈值经过搜索。相同折、种子还使用相同的批次打乱顺序；GRU 的目标标签排列由独立随机数流生成。该模型本身也按固定顺序逐步决定标签，因此实验比较的是具体生成设计，不能解释为“一切逐步模型都优于直接多标签模型”。

## 一键运行

进入上传后的文件夹，在 CPU 节点执行：

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests
python3 run_all.py --smoke-test --cpu-threads 2
python3 run_all.py --cpu-threads 6
```

冒烟测试仅执行每个方法的一次参数更新和验证集解码，不查看外层测试集，也不写正式结果。正式命令依次运行四种方法、三折、三个训练种子，共 36 次训练；每次 100 轮，batch size 64。训练时间可能较长。重复执行同一命令会跳过文件完整、协议哈希一致的已完成运行。需要把任务拆给多个作业时可指定：

```bash
python3 run_all.py --method sigmoid_matched --fold 2 --seed 17 --cpu-threads 6
```

多个作业并行写入同一 `results` 文件夹时，先由一个作业执行 `python3 run_all.py --init-only`，固定正式运行协议；之后按不同方法、折和种子分配作业，不要让两个作业写同一运行目录。默认一键串行运行不涉及并发写入。

全程使用 CPU。每次训练使用 AdamW（学习率 $3\times10^{-4}$、权重衰减 $10^{-4}$、AMSGrad）、梯度范数裁剪 1.0 和参数 EMA（衰减上限 0.995）。每轮按验证集完全匹配率、样本 F1、较早轮次选检查点。两种 sigmoid 模型和 Classifier Chain 的阈值候选为 0.05 至 0.95，步长 0.01；阈值并列时依次比较完全匹配率、样本 F1、Micro-F1 和较小阈值。所有方法仅在选定检查点上计算外层测试指标。

正式运行结束应出现 `COMPLETE 36/36 runs`。然后执行：

```bash
python3 analyze_results.py
```

分析脚本逐一核对病例 ID、真实标签、协议哈希和保存指标；它会生成 `results/analysis_report.md`。请把整个 `results` 文件夹复制回本机这个运行包所在目录。它包含每次运行的 `summary.json`、`history.json`、`predictions.json` 和 `best.pt`；分析时只需要前三种 JSON，但保留检查点便于复核。

## 评价范围

三折为按真实标签数分层的记录级内部交叉验证。每折 2380 条训练、420 条验证、1400 条测试记录。40 种症状和 10 种证候要素的词表作为事先固定的任务定义；模型参数只由对应训练折学习。4,200 条记录先前已用于方法探索，所以新划分用于检查受控比较在不同记录子集上是否持续；它不是未曾接触的新临床队列。没有患者 ID 或逐例采集日期，不能据此报告患者级或时间外验证。
